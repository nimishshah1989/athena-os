When producing design docs, architecture, plans, or research for the user, always ALSO produce a digestible visual version (HTML artifact — diagrams, plain language, minimal jargon). Large raw markdown files and deep technical prose don't work for him; he said "it becomes very hard for me to read through large-scale MD files... what you mentioned is so technical that I can barely make sense of it."

**Why:** Non-technical founder ([[user-profile]]) — the MD files remain the engineering source of truth in the repo, but alignment/decisions happen on the visual version.
**How to apply:** Keep writing full technical MDs for the repo (they drive the build), but every alignment-facing deliverable gets an HTML artifact companion: what it means, plain words, visual architecture, decisions needed from him. Explain like to a smart founder, not an engineer.
